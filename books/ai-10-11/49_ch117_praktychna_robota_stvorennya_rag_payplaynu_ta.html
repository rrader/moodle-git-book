Retrieval-Augmented Generation (RAG) — це провідна інженерна архітектура, яка поєднує можливості великих мовних моделей (LLM) з динамічним пошуком інформації у зовнішній базі знань. У цій практичній роботі ми побудуємо повноцінний RAG-пайплайн у візуальному середовищі Flowise та налаштуємо систему автоматичного фактчекінгу документів.

🌐 Робочий інструмент: Flowise AI

Flowise — це open-source UI для візуального конструювання LLM-додатків, ланцюжків LangChain та мультиагентних систем. Для виконання роботи використовується інстанс:
Відкрити Flowise (flowise.rmn.pp.ua) ↗

🎯 Мета роботи:

  • Засвоїти архітектуру RAG: розбиття тексту на чанки (Chunking), створення векторних ембедінгів (Embeddings) та семантичний ретривінг (Vector Retrieval).
  • Побудувати візуальний ланцюжок Conversational Retrieval QA Chain у Flowise.
  • Розробити спеціалізований промпт для автоматичного фактчекінгу завантажених документів.
  • Протестувати точність системи за критеріями виявлення галюцинацій та підтвердження цитатами.

📐 Архітектура сучасного RAG-пайплайну

Запити до звичайної LLM часто страждають від застарілих знань або галюцинацій. RAG розв'язує цю проблему за 5 послідовних кроків:

  1. Document Loader & Splitter: завантажує документ (PDF, DOCX, CSV) та ділить його на менші фрагменти (чанки, наприклад по 500–1000 символів з перекриттям chunk overlap: 100).
  2. Text Embeddings: нейромережа (наприклад, text-embedding-3-small або локальна bge-m3) перетворює кожен чанк на багатовимірний математичний вектор змісту.
  3. Vector Store: векторна база даних (In-Memory, Chroma, Pinecone) зберігає вектори для надшвидкого пошуку за косинусною схожістю (Cosine Similarity).
  4. Retriever: коли користувач ставить запитання, ретривер знаходить k найбільш релевантних фрагментів тексту в базі.
  5. QA Chain: мовна модель отримує запитання разом зі знайденими фрагментами і формує точну аргументовану відповідь.

📋 Покроковий порядок виконання роботи:

Крок 1. Підготовка вихідного документа

Оберіть для аналізу будь-який об'ємний документ обсягом не менше 3–5 сторінок:

  • Наукову статтю з відкритих архівів (arXiv, Google Scholar).
  • Офіційний регуляторний документ, закон чи технічну інструкцію.
  • Звіт або публічний паспорт відкритих даних.

Крок 2. Збирання пайплайну у Flowise

Створіть новий Chatflow та додайте на робоче полотно наступні вузли:

  1. Document Loader: виберіть PDF File Loader та завантажте ваш файл.
  2. Text Splitter: підключіть Recursive Character Text Splitter (встановіть Chunk Size: 800, Chunk Overlap: 100).
  3. Embeddings: підключіть OpenAI Embeddings (або аналог).
  4. Vector Store: додайте In-Memory Vector Store (з'єднайте його з Document Loader та Embeddings).
  5. Chat Model: підключіть ChatOpenAI (модель gpt-4o-mini або сумісна, temperature: 0.1 для мінімізації фантазій).
  6. Chain: додайте вузол Conversational Retrieval QA Chain, з'єднавши його з Vector Store та Chat Model.

🔍 Крок 3. Налаштування ланцюжка фактчекінгу (Fact-Checking Pipeline)

Відкрийте налаштування системного промпту у блоці QA Chain та налаштуйте сувору інструкцію фактчекера:

System Prompt для Фактчекера:
Ти — професійний аналітик-фактчекер.
Твоє завдання — перевірити твердження користувача виключно на основі наданого контексту документа.

Для кожного твердження сформулюй відповідь строго за шаблоном:
1. Вердикт: [✅ ПРАВДИВО / ❌ НЕПРАВДИВО / ⚠️ НЕВІДОМО]
2. Цитата з джерела: "..." (дослівний фрагмент із тексту документа)
3. Пояснення: стислий аналіз того, чому твердження відповідає або суперечить фактам.

СУВОРІ ОБМЕЖЕННЯ:
- Якщо інформація відсутня у наданих фрагментах, ЗАБОРОНЕНО додумувати чи спиратися на власні знання. Одразу став вердикт "⚠️ НЕВІДОМО".
- Жодних галюцинацій чи припущень.

Крок 4. Тестування системи

У вікні чату протестуйте фактчекер щонайменше 5 запитаннями різного типу:

  1. Правдиве твердження: прямий факт із тексту (має отримати вердикт ✅ ПРАВДИВО з точною цитатою).
  2. Фальшиве твердження: змінена цифра чи протилежне за змістом твердження (має отримати вердикт ❌ НЕПРАВДИВО зі спростуванням).
  3. Твердження за межами тексту: факт, якого взагалі немає у документі (має отримати вердикт ⚠️ НЕВІДОМО, підтверджуючи захист від галюцинацій).
  4. Складне порівняльне запитання: аналіз двох частин документа.
  5. Запит на структурований вивід: формування підсумкової таблиці виявлених фактів.
✅ Критерії успішного виконання:
  • Пайплайн успішно розбиває PDF-документ на чанки та векторизує їх.
  • Ланцюжок видає структуровані вердикти з точними цитатами першоджерела.
  • Система коректно відмовляється відповідати на питання за межами завантаженого контексту без галюцинацій.
