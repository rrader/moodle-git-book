У цій практичній роботі ми навчимося готувати реальні відкриті табличні дані для великих мовних моделей (LLM) за допомогою візуального середовища Orange Data Mining, генерувати структуровані текстові описи та створювати RAG-асистента з унікальною рольовою персоною (Persona).

💡 Чому табличні дані складні для LLM?

Звичайні мовні моделі ефективно читають зв'язний текст, але часто плутають рядки, стовпчики та статистичні агрегації у великих «сирих» CSV-файлах. Щоб RAG-система давала 100% точні відповіді, дані попередньо агрегують та конвертують у зрозумілі природномовні формулювання.

🎯 Мета роботи:

  • Завантажити та дослідити офіційний набір відкритих даних радіаційного стану АЕС України.
  • Побудувати візуальний пайплайн обробки даних у Orange Data Mining.
  • Виконати групування та агрегацію числових показників (Mean, Sum).
  • За допомогою віджета Feature Constructor згенерувати текстові формулювання для кожного об'єкта.
  • Налаштувати системний промпт із заданою персоною (роллю) для відповідей школярам.

📋 Покроковий порядок виконання роботи:

Крок 1. Підготовка середовища та завантаження набору даних

  1. Встановіть та запустіть Orange Data Mining (якщо ще не встановлено, завантажте з офіційного сайту: orangedatamining.com/download).
  2. Завантажте офіційний набір відкритих даних моніторингу радіаційного стану та скидів українських АЕС із порталу відкритих даних:
    Відкрити набір даних на data.gov.ua ↗

Крок 2. Побудова пайплайну в Orange Canvas

Створіть у середовищі Orange наступний ланцюжок віджетів:

[ CSV File Import ] → [ Select Columns ] → [ Aggregate ] → [ Feature Constructor ] → [ Data Table ] → [ Save Data ]
  1. CSV File Import: вкажіть шлях до завантаженого файлу з даними АЕС. Переконайтеся, що колонка station визначена як категоріальна (Text/Categorical), а показники скидів — як числові (Numeric).
  2. Aggregate: налаштуйте групування за назвою електростанції (Group by: station). Для числових показників виберіть розрахунок середнього (Mean) та суми (Sum):
    • volume → Mean та Sum
    • iodine_radionuclides → Mean
    • cs_137_emission → Mean
    • co_60_emission → Mean
    • index_radioactive_releas → Mean
  3. Feature Constructor: створіть нову текстову ознаку (String Feature) з назвою station_summary та запишіть формулу, що перетворює сухі цифри на зв'язний текст: 
    "На станції " + station + " середній об'єм води, що скидалась, був " + str(volume___Mean) + " м³. Сумарно скинуто " + str(volume___Sum) + " м³. Викиди радіонуклідів йоду: " + str(iodine__radionuclides___Mean) + " кБк/добу. Викиди цезію-137: " + str(cs_137_emission___Mean) + " кБк/місяць. Показник радіоактивного викиду: " + str(index_radioactive_releas___Mean) + "."
  4. Save Data: експортуйте підготовлені збагачені дані у форматі CSV або JSON для передачі в RAG.

🎭 Крок 3. Налаштування Персони (Persona) та промпту в RAG

Персона — це рольовий контекст, у якому штучний інтелект взаємодіє з користувачем. Замість сухого робота ми надаємо моделі характер, цільову аудиторію та стиль пояснення.

Приклад формулювання системного промпту:
System Prompt: Капітан Радіоактивність

«Ти — Капітан Радіоактивність, доброзичливий супергерой-еколог. Твоє завдання — пояснювати школярам складні офіційні екологічні звіти АЕС просто, наочно та з гумором.
Правила поведінки:
1. Завжди спирайся виключно на надані факти з бази знань, не вигадуй неіснуючих цифр.
2. Порівняння між станціями завжди оформлюй у вигляді чіткої Markdown-таблиці.
3. Пояснюй абстрактні об'єми та беккерелі через зрозумілі життєві аналогії (кількість олімпійських басейнів, відер води, порівняння з безпечним фоном бананів або гранітної бруківки).
4. Кожну відповідь закінчуй коротким розділом "💡 Екологічна порада від Капітана".»

Очікуваний формат табличного виводу моделі:
Станція Середній скид води Викиди Цезію-137 Рівень безпеки
ЗАЕС 12 345 м³ (≈ 5 басейнів) 10 кБк/місяць 🟢 В межах норми
ПАЕС 987 м³ (≈ 0.4 басейну) 50 кБк/місяць 🟢 В межах норми
✅ Завдання для звіту:
  1. Скриншот робочої схеми в Orange Canvas з налаштованим віджетом Feature Constructor.
  2. Фрагмент згенерованого текстового стовпчика station_summary для двох різних станцій.
  3. Приклад діалогу з RAG-асистентом, де чітко видно роботу заданої персони та порівняльну таблицю.
